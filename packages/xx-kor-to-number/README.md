# @cp949/xx-kor-to-number

한글 숫자 표현을 숫자로 바꾸는 함수 하나를 담은 라이브러리다. `"이십일억 사천칠백사십팔만 삼천육백사십팔"`, `"21억 4748만 3648"`, `"마이너스 하나"`를 읽는다.

## 설치

```bash
pnpm add @cp949/xx-kor-to-number
```

## 사용

```ts
import { koreanToNumber } from '@cp949/xx-kor-to-number';

koreanToNumber('이십일억 사천칠백사십팔만 삼천육백사십팔'); // 2147483648
koreanToNumber('1만 2천3백4십5'); // 12345
koreanToNumber('12,345원'); // 12345
koreanToNumber('마이너스 이십'); // -20
koreanToNumber('영점 오'); // 0.5
koreanToNumber('abc'); // NaN
```

`koreanToNumber(input: string): number`는 읽을 수 없으면 `NaN`을 돌려준다. 던지지 않는다.

### 읽는 표현

- 아라비아 숫자, 쉼표(`1,000`), 소수점(`.` 또는 `점`).
- 한자어 숫자: 영, 일, 이, 삼, 사, 오, 육(륙), 칠, 팔, 구.
- 고유어 숫자 1~9: 하나, 둘, 셋, 넷, 다섯, 여섯, 일곱, 여덟, 아홉.
- 단위: 십, 백, 천, 만, 억, 조, 경, 해. 아라비아 숫자와 섞어 쓸 수 있다(`2십1억 4천7백4십8만`).
- 부호: 앞에 오는 `-`, `+`, `마이너스`, `플러스`.
- 숫자 뒤에 붙은 단위 글자(`원`, `개`, `km`)는 무시한다.

## 지원 환경

- 브라우저: Chrome 75 이상. Node에서도 동작한다.
- 번들: 문법은 ES2019 수준이다. `pnpm check:escompat`가 빌드 결과와 Chrome 75에 없는 API 이름을 검사한다.
- ESM(`import`)과 CommonJS(`require`)를 모두 지원한다.

## 알려진 한계

원본에서 옮긴 동작이다. 바꾸지 않고 테스트로 고정했다.

- 숫자로 읽을 수 없는 글자는 버리고 남은 글자만 읽는다. `이목구비`는 `NaN`이 아니라 29다. `이`와 `구`만 남는다.
- 숫자 뒤에 붙은 한글 숫자 글자도 숫자로 읽는다. `10일`은 101이고 `500이`는 5002다.
- 고유어 서수(열, 스물, 서른, 마흔 등)는 읽지 못한다. `서른`만 주면 `NaN`이다. `서른이다`는 2다.
- 단위는 `해`까지만 읽는다. `자`와 `양`은 단위로 읽지 않고 버린다. `1자`는 1이다.
- 결과는 `number`다. 2^53 - 1(9007199254740991)을 넘는 값은 `number`의 정밀도 한계를 따른다. 1e21 이상에서는 소수부를 버린다.
- `1e3`처럼 지수 표기는 읽지 않는다. 숫자만 남겨 13이 된다.
